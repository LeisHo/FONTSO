FONTSO -- CODE SUMMARY
================================================================================

Status: see ../README.md for the project-structure layout and how to run it;
this file is a quick orientation pointer into the actual code, not a
duplicate of the README's tree.

--------------------------------------------------------------------------------
FILE MAP

THE LABORATORY (lab/) -- the live project.

- `lab/index.html` -- mount point: a full-bleed canvas plus the dev
  panel's markup, copied verbatim from the shared template.
- `lab/devpanel.js`, `lab/devpanel.css` -- the workspace-standard dev
  panel, a VERBATIM copy of .claude/TEMPLATE_DEV_PANEL.html's <script>
  and <style> blocks (the script differing by exactly one splice line).
  A second, independent copy from the root scaffold's, so lab/ stays
  liftable as a whole.
- `lab/lab.css` -- only what the panel does not own: the canvas, the
  legend, and the hand-built widgets (file input, char buttons, report,
  JSON), styled from the panel's own custom properties so they follow
  its theming.
- `lab/lib/opentype.mjs` -- opentype.js 2.0.0 (MIT), vendored MINIFIED build.
  The only dependency. Minified deliberately: see the gotchas below.
- `lab/src/config.mjs` -- EVERY tunable number in the pipeline, each with a
  note on what breaks at either extreme. No other module hard-codes a
  threshold. Start here when tuning.
- `lab/src/fontLoader.mjs` -- stage 0. The only module that knows opentype
  exists; everything downstream sees plain geometry.
- `lab/src/glyphExtract.mjs` -- stage 1. TEXT (any string, one character
  being the degenerate case) -> real outline commands plus flattened
  contours. Lays glyphs out along the baseline with the font's own
  advance widths and kerning, so everything downstream is unchanged and
  separate letters fall out as separate graph components. Owns the
  coordinate-space contract.
- `lab/src/rasterize.mjs` -- stage 2. Outline -> binary mask via canvas fill.
  Also labels mask components and their areas.
- `lab/src/skeletonize.mjs` -- stage 3. Zhang-Suen / Guo-Hall thinning plus
  redundant-pixel removal.
- `lab/src/skeletonGraph.mjs` -- stage 4. Skeleton -> nodes/edges/components.
- `lab/src/cleanup.mjs` -- stage 5. Spur pruning, speck dropping, RDP
  simplification, Chaikin smoothing.
- `lab/src/vectorize.mjs` -- stage 6. Graph -> segments in raster px AND font
  units, with the transform relating them.
- `lab/src/fontStore.mjs` -- in-memory registry of imported font bytes,
  base64 transport, and the saved/unsaved bookkeeping Sync uses. NOT
  mirrored to localStorage: the 5MB quota would be exhausted by two
  base64 fonts, and a store that silently drops the third is worse than
  one that is simply empty on reload. Persistence is the server's job.
- `lab/src/routing.mjs` -- nearest-curve routing: given the pen's
  position and the curves not yet drawn, which to go to next and where
  to enter it. Shared by the midline traversal (component order + entry
  node) and the tween animation route.
- `lab/src/traversal.mjs` -- stage 7. Graph -> ordered route with explicit
  pen-up connectors.
- `lab/src/distanceTransform.mjs` -- exact Euclidean distance transform
  (Felzenszwalb, linear-time separable). Supplies the local stroke
  half-thickness that the tween needs; nothing else in the pipeline can
  provide it (the skeleton knows where the middle is, not how thick the
  stroke is around it). Approximate chamfer DTs were rejected: their
  error is direction-dependent and would show as the tween drifting off
  the outline on diagonals but not on stems.
- `lab/src/tween.mjs` -- centreline -> outline morph, plus the weld pass that joins crossed offset curves at junctions. Two offset curves
  per skeleton edge at progression x radius, plus the fine-tuning
  (radius scale/smoothing, normal smoothing, resampling, terminal
  extension) and the animation route built from the tween geometry.
- `lab/src/pipeline.mjs` -- orchestration and the debug-JSON projection. The
  ONLY file that knows the stage order.
- `lab/src/viz/renderer.mjs` -- layered canvas renderer. Also owns
  DEFAULT_VIEW, the RENDER-ONLY settings (path thickness / colour /
  progressive inking). Deliberately NOT in config.mjs: that is the
  pipeline's parameter set and every change to it re-runs the whole
  glyph->skeleton pass, which would be pure waste for a colour change.
- `lab/src/viz/animator.mjs` -- constant-speed dot along the route.
- `lab/src/viz/viewport.mjs` -- zoom/pan gestures (wheel + right-drag on
  desktop, pinch + two-finger drag on touch). Owns no geometry: it
  mutates the renderer's existing view transform and asks for a redraw.
- `lab/src/app.mjs` -- UI wiring. Contains no geometry. Registers every
  laboratory control into the dev panel via window.renderFontLabDevGroups
  (7 groups: Font & Character, Layers, Animation, Rasterisation,
  Skeletonisation, Cleanup, Traversal), plus the pipeline report and
  debug JSON as subgroups of the built-in Debug group.
- `lab/test-fonts/` -- OS faces copied in for comparison. Gitignored;
  manifest.json is tracked.

THE SCAFFOLD (root) -- built earlier, currently unused by the laboratory.
Kept because it is verified working and is the workspace standard if this
project ever grows a real front end. `index.html`, `src/main.js`,
`src/style.css`, `src/devpanel/devPanel.js` (verbatim template copy),
`lib/ui-engine/` (vendored v0.2.6), `api/save-settings.js`.

- `scripts/active/serve.py` -- the dev server. Required, not optional.
  Also implements /api/save-settings and /api/fonts (directory listing of
  data/Fonts + lab/test-fonts, so a dropped-in font needs no manifest).
- `data/raw/inherited-handyset-2026-09-22/` -- pre-existing HANDYSET files
  moved aside, not deleted. Gitignored. Nothing live reads them.

--------------------------------------------------------------------------------
ARCHITECTURE

Strictly linear, one direction, no stage importing another stage:

  font file
    -> fontLoader      (opentype parse)
    -> glyphExtract    (outline commands + contours, font units)
    -> rasterize       (binary mask + mask-component labels/areas)
    -> skeletonize     (1px skeleton)
    -> skeletonGraph   (nodes / edges / components)
    -> cleanup         (prune -> REBUILD graph -> repeat, then simplify/smooth)
    -> vectorize       (segments in px + font units)
    -> traversal       (ordered route + connectors)
    -> viz             (render + animate)

pipeline.mjs is the only file that knows this order. cleanup.mjs and
skeletonGraph.mjs have a deliberate two-way relationship: cleanup prunes by
ERASING PIXELS from the bitmap and the pipeline then rebuilds the graph from
scratch, rather than performing incremental graph surgery. Slower, and immune
to the desynchronisation bugs that approach invites.

Three coordinate spaces exist and are never mixed implicitly: font units
(opentype's own), raster px (the mask), screen px (the canvas). glyphExtract
declares the contract; rasterize emits the explicit toRaster/toFont pair;
vectorize reports geometry in BOTH px and font units so no consumer is
coupled to whatever rasterEmHeight happened to be set.

--------------------------------------------------------------------------------
GOTCHAS

- Fonts are committed as their OWN files under data/processed/fonts/,
  never embedded in the settings JSON. A 1.8MB face is ~2.4MB of base64
  and Sync rewrites the whole settings document every time, so embedding
  would add a multi-megabyte git object per save.
- serve.py implements /api/save-settings in-process. The token comes
  from the GITHUB_TOKEN environment variable ONLY -- never from a file,
  never logged, never echoed. Without it the endpoint returns 503 and
  the client falls back to localStorage by design.
- config.rasterEmHeight is BOTH the glyph size and the raster
  resolution; there is no separate "font size". It is surfaced once, in
  the Text group, labelled Font Size. Cost tracks raster AREA, so long
  text at a large size is genuinely slow (43 chars at 256 wrapping to
  400px is 434x8997 and ~4s); the pipeline warns past 1.5M px.
- `python -m http.server` CANNOT serve this project -- it sends .mjs as
  text/plain and browsers reject that for ES modules. Use
  scripts/active/serve.py.
- The local static server intermittently truncates responses above ~250KB
  (200 OK alongside net::ERR_CONNECTION_RESET), which silently breaks the
  whole module graph or a font load. This is why opentype.js is vendored
  minified and why loadFontFromUrl retries three times. If the lab loads with
  `window.fontLab` undefined, retry the navigation before suspecting code.
- Pixel classification MUST use crossing number, not 8-neighbour count. A
  diagonal staircase corner has 3 neighbours and is not a junction.
- Redundant-pixel removal MUST count true connected groups among a pixel's
  neighbours, not ring transitions. Ring order says N and W are far apart;
  they physically touch.
- Never delete a tiny self-loop's PIXELS -- only the edge. Those pixels are a
  junction's connective tissue; deleting them severed Comic Sans 'H'.
- Never filter components by skeleton LENGTH. A dot and a speck are
  indistinguishable by length. Use source mask area.
- opentype.js v2 nests the name table under names.windows / names.macintosh,
  not flat at names.fontFamily.
- opentype.js 2.0.0's font.getKerningValue() takes the GPOS path whenever
  a font has GPOS kerning tables and NEVER falls back to the parsed pair
  table, returning 0 even when the pair exists. Measured: Arial parses
  909 pairs, Times 867, both return 0 for A/V while kerningPairs holds
  -152. kernBetween() in glyphExtract.mjs consults kerningPairs when the
  accessor yields nothing. Do not "simplify" it back to a bare
  getKerningValue() call -- that silently un-kerns every string.
- Browser-pane JS evaluation is throttled hard when the pane is hidden; a
  multi-font sweep will time out. Front the tab first.
- The distance field is computed ONCE per pipeline run and handed out on
  the result. Tween settings re-offset the cached polylines against it
  (O(points)) and redraw -- they never re-rasterise or re-thin. Moving a
  tween control into config.mjs would silently make every slider tick a
  full pipeline pass.
- Pipeline parameters (config.mjs) re-run the pipeline on change;
  render-only settings (renderer.mjs's DEFAULT_VIEW) only redraw. The
  delegated listener routes each control id to the right one via
  CONFIG_BY_CONTROL_ID / VIEW_BY_CONTROL_ID. Putting a render setting in
  the wrong map costs a full pipeline re-run per slider tick.
- The template's click-to-edit readout (S12h) commits a typed value with
  `slider.dispatchEvent(new Event('input', {bubbles:true}))` and NEVER
  dispatches 'change'. A delegated listener bound only to 'change'
  therefore misses every TYPED slider edit: the handle moves, the readout
  updates, and the state silently keeps its old value. This shipped, and
  surfaced as "I set Tween Progression to 1 but it only goes halfway" --
  halfway being that control's 0.5 default, which it was still on. Handle
  BOTH events, gated on whether a pointer is down in the panel (drag =>
  wait for 'change'; typed/synthetic => apply immediately).
- Letter buckets are ordered by the glyph's READING-ORDER INDEX, never
  by geometry. An earlier version sorted by position using a per-letter
  vertical tolerance, which made the comparator inconsistent (A-vs-B
  used A's tolerance, B-vs-A used B's) and Array.sort then produced an
  arbitrary order - measured: wrapped text drew 'k' before 'i' and 'c'.
  The layout stage already knows reading order; do not re-derive it.
- Each segment's letter is assigned in FONT UNITS against the glyph's
  pen position and advance width (vectorize.mjs). Deriving letter
  boundaries from raster pixel clusters would merge any two letters
  whose ink happens to touch.
- adaptiveWidth.mjs turns a polyline into a variable-width RIBBON using
  the distance field. Canvas lineWidth is a property of a whole path, so
  a width that changes vertex by vertex cannot be a stroke at all - it is
  a filled polygon, and a closed curve needs two rings filled even-odd so
  a counter stays a hole rather than being flooded.
- Its outward direction comes from the FIELD GRADIENT, not from whichever
  side tween.mjs offset toward. -grad points at the nearest boundary by
  definition, which keeps the module independent of the tween stage and
  stays correct for a welded curve whose vertices came from two different
  parents and no longer share a side. It is only ill-conditioned ON the
  medial axis, which is exactly the case the two-sided mode covers, so
  the fallback there is the tangent normal.
- Its geometry helpers are deliberately DUPLICATED from tween.mjs rather
  than imported. lab/ is meant to be liftable as a geometry engine, and a
  width module that drags the whole welding stage in behind it would
  defeat that. They are a dozen lines each.
- routeOrder.mjs owns the animation route's ORDER: the stops a user
  sees and clicks, manual overrides, and the learned per-font+character
  stroke order. All three turn on one question - what identifies a stop -
  which is why they live together rather than being spread across the
  route builders.
- A learned order is stored as NORMALISED GLYPH-SPACE POSITIONS, never as
  ids or indices. `edgeId:left` is assigned by the skeleton graph, so any
  change to raster height, thinning or pruning renumbers everything; a
  position in the glyph's own bounding box survives all of it. Matching
  is greedy nearest-pair-first, so one bad early match cannot cascade,
  and unmatched stops keep their computed position rather than being
  forced somewhere.
- Both route builders emit the same `stops` shape, so the Route Points
  layer and Switch Point Order work against either without branching.
  The midline route re-flattens through flattenOrdered() when an
  override applies, because its precomputed animation was flattened in
  traversal order and cannot express a reorder.
- routing.mjs keeps "which curve next" and "where do I enter it"
  SEPARATE. Each curve proposes admissible entry points; selection is
  always pen-to-entry travel. Letting an entry rule's own distance
  double as the selection metric was a real bug: the loop rule measures
  to a midline ANCHOR, so a loop sitting near some anchor won the
  "nearest" contest from across the glyph.
- A loop offers one candidate per midline endpoint, not a single global
  best, or its entry can be pinned far from the pen.
- Whether a tween curve is a LOOP must come from the skeleton edge's
  own isLoop flag, never from comparing the curve's first and last
  point. Resampling and smoothing move a ring's seam apart -- measured
  at 0.2162px on Comic Sans 'O' -- so a coordinate test reports a real
  ring as open, and loosening the epsilon only trades one wrong answer
  for another.
- Zoom must be anchored to the pointer, and the canvas backing store is
  DPR-scaled while events report CSS pixels; skipping that conversion
  makes zoom drift away from the cursor on any non-1x display.
- Dev-panel config controls are wired by ONE DELEGATED listener on
  #devPanel, never per element. A Mobile/Landscape twin is created only
  when its checkbox is ticked, long after wire-up, so per-element
  listeners would leave it driving nothing -- silently.
- Testing that delegated wiring requires a BUBBLING event:
  `new Event('change')` does not bubble and will never reach the panel,
  producing a false negative that looks exactly like broken code. Use
  `new Event('change', {bubbles: true})`. Same family as the documented
  `.click()`-vs-pointerdown trap in the template's own notes.
